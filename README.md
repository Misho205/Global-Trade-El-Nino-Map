# Global-Trade-El-Nino-Map

An interactive 3D Earth atlas exploring international trade, transport corridors
and El Nino climate observations. Built with React, Vinext, Cesium and Cloudflare Workers.

## Project status

Early-stage research and educational software. The project's display name has
changed from TerraTrade; some application branding and technical identifiers still
use the earlier name. Documentation describes the current source, not proof that
every feature is enabled on the hosted version.

The full security-audit workflow remains incomplete. Functional tests and local
build checks are not a security certification. Review [SECURITY.md](SECURITY.md).

## Features

- Rotatable globe with country labels, flags, boundaries, Esri imagery and terrain.
- Curated schematic sea, rail and air corridors for goods, energy and commodities.
- UN Comtrade annual bilateral statistics and WTO agreement records.
- A 50-year date-selection window, subject to source availability and classification.
- NOAA climate discussion, historical ONI, eight coastal gauges and tide predictions.
- Historical/current ENSO comparison and explanatory climate pages.
- 36 bundled AlphaEarth annual port-region previews, labeled 2017-2025 in the manifest.
- Browser-language based Google Translate widget, with an English fallback.
- D1 last-valid snapshots, bounded retries, refresh status and a background collector.

## Limitations

Routes are illustrative, not live vessel/aircraft tracking or every company's
shipping itinerary. Trade values are annual statistics, not individual contracts.
Political alliances do not establish why a transaction occurred. Selecting a past
date does not reconstruct historical imagery, borders or route geometry.

NOAA astronomical tide predictions exclude ENSO/storm residuals. No global
ENSO-driven water-height or flood model is connected. ONI and RONI are different
indices; a forecast is not an observation. AlphaEarth previews are static embedding
visualizations, not photographs or real-time water measurements.

## Quick start

Requirements: Node.js **>=22.13.0**, npm and Git. Use an up-to-date compatible Node
release. Commands run from the directory containing `package.json`.

```sh
npm ci
npm run dev
```

Open the loopback URL printed by the terminal (normally port 5173). Current public
feeds do not require project API keys, but network access, quotas and service terms
still apply. A missing D1 binding is explicitly reported; it does not mean a
background collector is active.

## Build and validate

```sh
npx tsc --noEmit --incremental false
node --experimental-strip-types --test tests/snapshot-cache.test.mjs tests/cloudflare-readiness.test.mjs
npm run build
```

Run commands separately and stop on failures. `npm run lint` is available; there is
no `npm test` script. Node's SQLite module may print an experimental feature warning.
For a built local preview, run `npm run start`.

### Local D1

Build once, then apply the initial migration **once to an empty local database**:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_mysterious_elektra.sql
```

Restart preview and inspect `/api/data-status`. Local state is not production
state. Future migrations must be applied in order without replaying applied SQL.

## Automatic updates

The browser polls climate every 15 minutes, water every 6 minutes, and trade and
agreements hourly. The independent collector needs D1 **and an activated scheduler**:

| Data | Collector refresh eligibility |
| --- | --- |
| NOAA climate discussion and ONI | 15 minutes |
| Today's water readings for eight stations | 6 minutes |
| Complete WTO lists | Daily |
| Annual trade queries used in the last seven days | Daily, at most three per run |

Actual freshness also depends on publication frequency, scheduler cadence,
caching, errors and backoff. A six-minute Cron does not guarantee a new observation
every six minutes. AlphaEarth, routes and alliance context are not regenerated by
the collector. See [DATA-UPDATES.md](DATA-UPDATES.md).

## Deploy

Publish the whole source repository to **Cloudflare Workers Builds**, not just
`public/`. Create a real D1 database, apply migrations, configure build variables
and deploy generated `dist/server/wrangler.json`. Do not hand-edit generated config.

Follow [the deployment guide](docs/DEPLOYMENT.md). Protect the first deployment
with Access and verify actual Cron invocations and persisted readback.
